## 2024-06-25 - [Optimize reflection and process waiting in Shizuku Command Execution]
**Learning:** In Android apps utilizing Shizuku via reflection, calling `java.lang.reflect.Method.invoke()` repeatedly is expensive. More importantly, calling `Process.waitFor()` on the main thread drastically freezes the UI because it relies on the blocking IO state of the executed native process. Calling shell wrappers (`sh -c`) pervasively has unnecessary string-parsing and wrapper-spawning overhead.
**Action:** Use a `by lazy` block to cache reflection method lookups. Make command-executing functions `suspend` and shift blocking operations (like `process.waitFor()`) to `Dispatchers.IO` using `withContext(Dispatchers.IO)`. Pass array-based commands directly (`List<String>`) to hidden process APIs instead of piping them through `sh -c`.
